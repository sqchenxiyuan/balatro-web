# 构筑机制、实现重点与待验证项

调研日期：2026-11-07。本页区分公开规则、依据规则得到的推导，以及后续实现建议。没有对原版运行结果做自动化验证。

## Joker 应按能力和触发阶段分类

稀有度只控制出现机会与内容池，不足以描述技能。一个 Joker 可以同时有成长、独立计分和回合结束事件。

| 能力类型 | 代表与当前数值 | 需要的状态 / 事件 |
| --- | --- | --- |
| 固定筹码 | Ice Cream 初始 +100，每次出牌 -5 | 独立计分、出牌后衰减 |
| 成长筹码 | Wee Joker 每张计分的 2 永久 +8；Runner 含顺子时 +15 | On scored 与手牌判定；当前累计值 |
| 固定加倍率 | Joker +4；Fibonacci 每张计分的 A/2/3/5/8 +8 | 独立阶段与逐牌阶段不能混淆 |
| 成长加倍率 | Green Joker 每次出牌 +1、每次弃牌 -1 | 出牌 / 弃牌分别更新 |
| 乘倍率成长 | Constellation 每次用星球 +×0.1；Hologram 每次加牌 +×0.25 | 使用消耗品、永久加牌 |
| 消耗强化成长 | Vampire 每张计分强化牌 +×0.1，并移除强化 | 计分前后及强化移除的准确时点 |
| 计分牌重触发 | Hanging Chad 重触发第一张用于计分的出牌 2 次 | 每张牌的触发次数与位置 |
| 留手倍率 | Baron 每张留手 K ×1.5；Mime 重触发留手能力 | held cards，独立于 scoring cards |
| 经济转分数 | Bull 每 $1 +2 Chips；Bootstraps 每 $5 +2 Mult | 取当时资金，不能只在商店结算一次 |
| 规则改写 | Four Fingers：4 张同花/顺子；Shortcut：顺子可隔 1 个点数 | 牌型识别阶段 |
| 能力复制 | Blueprint 复制右侧；Brainstorm 复制最左 | 复制兼容、目标、阶段与顺序 |
| 牌堆改造 | DNA 复制首手单牌；Trading Card 销毁首次单张弃牌并给 $3 | 永久牌堆与当前手牌同时变化 |
| 生存 / Boss 对策 | Mr. Bones 达目标 25% 时可救命并销毁；Luchador 卖出禁用当前 Boss | 失败拦截、出售事件 |

数值来源：[Jokers](https://balatrowiki.org/w/Jokers)。完整卡片价格、解锁和英文描述在 [04](04-joker-catalog.md)。

“contains a Pair”和“本手牌型恰好为 Pair”必须分开。三条等牌型可以包含对子结构，使某些低级组合 Joker 同时有效；Four Fingers、Shortcut 需要参与牌型计算本身。

## 五类有代表性的构筑

这些是依据公开效果整理的构筑例子，用于理解机制覆盖面，不作为保证胜率的攻略。

1. **基础计分与成长**：牌型升级 + 稳定筹码 + 加倍率 + 后置乘倍率。能验证常规独立 Joker 顺序。
2. **Photograph + Hanging Chad**：第一张计分的人头牌每次触发 Photograph ×2，Chad 额外触发两次时，该部分合计为 `2³ = ×8`。应同时验证这张牌的筹码和其他逐牌能力也被重触发。
3. **Baron + Mime**：留手 K 才触发。3 张普通 K 的倍率因子为 `1.5³ = 3.375`；加一个 Mime 后为 `1.5⁶ = 11.390625`。这是该组合贡献的倍率因子，不是整手最终分数。
4. **经济转分数**：存钱到基础利息上限，利用 Bull / Bootstraps 将资金转换成计分能力；消费会同时降低以后利息与当前计分。
5. **压缩和复制牌堆**：Hanged Man / Trading Card 删除无用牌，Death / DNA / Cryptid 复制目标牌，提高四条、五条、红蜡封玻璃等组合的稳定性。

这些构筑分别要求计分顺序、留手重触发、经济快照、永久牌堆和概率条件正确。只实现一张 Joker 的独立数值不能验证整套交互。

## 卡牌修饰不是一个枚举

公开规则允许普通扑克牌同时有 **1 个 Enhancement + 1 个 Seal + 1 个 Edition**；Joker 有 1 个 Edition 与兼容的多个 Sticker。永久成长（如 Hiker）还需独立保存。不能用单个 `card.specialType` 同时表达它们。

| 层 | 关键数值 / 边界 |
| --- | --- |
| Enhancement | Bonus +30 Chips；Mult +4；Glass ×2、1/4 碎裂；Steel 留手 ×1.5；Stone +50；Gold 回合结束留手 +$3；Lucky 独立 1/5 得 +20 Mult、1/15 得 $20 |
| Seal | Gold 每次计分 +$3；Red 额外触发 1 次；Blue 结束时按最终所打牌型创建星球；Purple 弃牌创建塔罗 |
| Edition | Foil +50 Chips；Holographic +10 Mult；Polychrome ×1.5；Negative 扩展对应槽位 |
| Sticker | Eternal 不可卖/销毁；Perishable 五回合失效；Rental 每回合 -$3；前两者互斥，Rental 可叠加 |
| 临时状态 | debuffed、face_down、forced_selected 含义不同，不能统一视作“卡不能用” |

来源：[Card modifiers](https://balatrowiki.org/w/Card_modifiers)、[Debuffed](https://balatrowiki.org/w/Debuffed)、[Perishable](https://balatrowiki.org/w/Perishable)、[Rental](https://balatrowiki.org/w/Rental)。

- Debuffed 普通牌仍保留大多数牌型识别用途，但不提供自己的筹码与被禁用效果。Wild 失效时退回基础花色，Stone 不恢复原点数和花色。
- Face-down 牌仍按真实值识别和计分，只是玩家看不到；排序和揭示行为属于观察规则。
- Rental 在 Joker 失效后仍收费。Perishable 在赢下第五个盲注后、Cash Out 前失效，某些 Cash Out 经济 Joker 因此只有四次收入。
- 版本出现率依生成途径区分。商店 Joker 的默认 Foil / Holo / Poly / Negative 为 2% / 1.4% / 0.3% / 0.3%；Standard Pack 普通牌的默认 Foil / Holo / Poly 为 4% / 2.8% / 1.2%，不能共享同一个概率表。Hone / Glow Up 的完整表保存在 `Card_modifiers` 的采集记录。
- 改强、蜡封覆盖与 Death 复制不是同一操作。Death 将左卡变成右卡，会复制强化、版本、蜡封和额外筹码等属性；应保留卡实例身份相关的临时状态规则，不能直接把两个对象引用设成同一个对象。[Death](https://balatrowiki.org/w/Death)

## Blueprint / Brainstorm 的边界

来源：[Blueprint](https://balatrowiki.org/w/Blueprint)、[Brainstorm](https://balatrowiki.org/w/Brainstorm)。

社区列出 29 张完全不兼容 Joker。即使兼容，也不能认为“复制整张卡”：

- 不复制 Edition、Sticker、目标卡自己的成长更新、通常的被动手牌上限等。
- Stuntman 的 +250 Chips 可复制，-2 Hand size 不复制。
- 对概率型效果，复制体可以独立掷骰，不应共用目标 Joker 的一次随机结果。
- Blueprint / Brainstorm 可以形成复制链，需处理失效目标、无目标和循环，不能无限递归。
- 当前手牌计分时复制谁，与赢下该关后的留手/回合结束事件使用谁，存在时点差异；不能把所有流程都绑定到同一张静态截图的顺序。

这些规则需要“可复制能力 + 事件上下文 + 来源与目标”模型。公开资料不足以保证复制所有罕见边界都正确，实施前应逐项固定案例。

## 随机性与存档

公开 [Seeded](https://balatrowiki.org/w/Seeded) 页面说明种子影响商店、牌序、Boss、包与概率效果，但也明确缺少随机池/队列的完整技术细节。**相同种子字符串不意味着任意自写 PRNG 可以复现原版同种子的所有结果。**

后续实现可先满足“本复刻相同版本、相同种子、相同动作得到相同结果”，把商店、牌序、包、Boss、概率效果拆成可保存的随机流。若目标进一步要求兼容原版种子，就还需单独研究原版 RNG、key/queue、内容池过滤和每次随机调用的消耗顺序。

完整存档至少应覆盖：永久牌堆与卡身份、抽牌堆/弃牌/手牌、Joker 顺序与成长值、消耗品顺序、牌型等级和次数、Ante/Boss/轮次、资金、优惠券、标签队列、贴纸倒计时、随机流状态、解锁进度。

种子局的解锁和统计行为不能直接套用普通随机局。Wiki 也记录了桌面/移动端统计的差异，应在选定目标平台后确认。

## 推荐的复刻分期

以下为实现建议，本阶段未开始编写游戏。

| 阶段 | 范围 | 通过标准 |
| --- | --- | --- |
| 1：规则内核 | 12 牌型、计分牌集合、等级、筹码/倍率、强化/蜡封、确定性随机 | 可输出逐事件计分日志，固定例子结果一致 |
| 2：完整单局 | 红牌组/白注、Ante 1–8、商店、利息、包与代表性 Joker | 从开局到胜负可完整游玩和存档，不依赖 UI 推进规则 |
| 3：内容覆盖 | 150 Joker、全部消耗品、券、15 牌组、Boss/标签 | 逐种能力分类验证，复制/重触发/销毁交互稳定 |
| 4：完整进程 | 8 难度、20 挑战、收藏解锁、Endless、表现与音效 | 难度和挑战规则可组合，经济/概率与目标版本一致 |

初版只做少量 Joker 可以验证可玩闭环，但应明确标记为原型，不能称为内容完整复刻。

## 已收集与尚缺证据

**已完成：**公开全量内容目录、精确的 Ante 1–8 和牌型数值、官方 1.0.1f 变化交叉核对、主要计分阶段、经济/概率生成条件，以及数据来源记录。

**仍需在实施阶段补证：**

1. 原版运行对照：组合牌型的边缘识别、部分 Joker 的“成长先于本次生效”时点、Blueprint 链、Boss 与销毁的冲突。
2. 数学边界：各阶段取整、极大数、Endless 的精确增长公式；已采到的科学计数法展示表不能替代公式。
3. 内容池完整实现：收集解锁、隐藏牌型、标签/Boss 首次可出现 Ante、重复限制、Eternal/Perishable 排除名单及贴纸联合分布。
4. 来源冲突：Wiki 将 Illusion 描述为可生成强化/版本/蜡封，但备注记录 1.0.1o 存在商店普通牌不生成蜡封的缺陷。需要明确选择“复现该版本实际行为”还是“按说明实现”，不能静默混用。
5. 表现：布局、拖拽、动画、计分节奏、音效和移动端交互未做逐帧研究。本资料没有采集原版素材。
6. 版本：开始实现前再次确认目标客户端，尤其 1.1 是否正式上线与数值是否变化。本资料中的预告不作为已发布规则。

可以先按上述资料独立实现规则。若将来需要原版种子兼容或精确到缺陷与时序的行为一致性，再补对应运行证据。
