# Web 复刻技术选型与浏览器 JS API

日期：2026-11-07。状态：正式游戏的技术方案与接口草案。另有 [视觉交互样片](12-lookdev-review.md) 提供仅限固定场景的 `getState()` / `dispatch(action)`，不能视为完整规则与接口已实现。

## 已确认的需求与边界

游戏在浏览器内运行，对外提供 **读取游戏状态、执行游戏操作** 两个 JavaScript 接口。其他人可在网页中调用这些接口游玩。策略函数的注入、执行、调度、策略管理以及批量实验由策略平台负责；游戏主体只交付可游玩的网页、可直接调用的接口和使用说明。

此前“两种都支持”仍指可控制当前网页里的一局，以及可供平台无界面运行；这不要求游戏提供 HTTP 服务。本文按用户的最新澄清修订，取代此前服务端持有对局、HTTP API 与 WebSocket 的方案。

## 推荐技术

**TypeScript 独立规则内核 + React / PixiJS 网页 + Vite + 浏览器 JS SDK。**

| 层 | 选择 | 职责 |
| --- | --- | --- |
| 规则内核 | TypeScript，纯模块 | 牌型、计分、Joker、商店、Boss、阶段、随机性 |
| 网页表现 | React + CSS；PixiJS 8 用于卡桌表现 | 菜单、布局、卡牌交互、计分事件播放 |
| 对外接口 | TypeScript/JavaScript SDK，页面暴露 `window.balatro` | 状态读取、语义命令（含开局/重开） |
| 构建 | Vite + TypeScript | 静态网页与可导入的规则/SDK 模块 |
| 本地存档 | 按需使用 IndexedDB | 浏览器保存与继续游戏 |
| 验证 | Vitest + Playwright | 规则验证、JS 接口与网页操作的一致性 |

框架的小版本在实施时锁定。Vite 开发服务只负责开发时加载网页，生产产物可静态部署，游戏状态由页面内的游戏实例持有。

## 同一局的调用路径

```text
鼠标 / 触屏 ──────────┐
                     ├── Game SDK ── 规则内核（页面内同一个实例）
页面中的外部 JS ──────┘       │
                            └── 状态 / 事件 ── React / PixiJS
```

页面对外暴露的 `window.balatro` 必须指向当前画面正在使用的实例。网页按钮和外部调用走同一条命令路径，不允许各自持有一份可写状态。规则内核不依赖 DOM、React、PixiJS 或全局 `window`。

策略平台如何加载代码、何时调用、是否放进 iframe/Worker、如何对接模型，由平台实现。游戏层不内置策略编辑器、策略循环、模型调用或评测调度器。

## 最小对外接口

以下是概念接口，尚未对应可安装的包：

```ts
interface GameAPI {
  getState(): GameStateView;
  dispatch(action: GameAction): Promise<ActionResult>;
}

declare global {
  interface Window {
    balatro: GameAPI;
  }
}
```

- `getState()`：返回当前阶段、牌、资金、商店等可观察状态，以及当前操作约束。
- `dispatch(action)`：执行出牌、弃牌、购买、使用消耗品等语义操作，返回执行结果；`new_game` 操作按 seed、牌组、难度等参数开局或重开。

外部按“读取状态 → 执行操作并等待完成 → 再读取状态”调用即可。状态变化和动画通知由游戏内部处理，对外不提供订阅接口，也不需要依靠定时轮询判断一次操作是否完成。

状态带 `revision`，便于调用方关联操作与画面。返回值应是与内部可变对象分离的快照，外部修改它不能改变游戏。非法操作返回明确错误，且不能扣钱、耗费次数、消耗随机数或留下部分效果。

调用示意：

```js
const game = window.balatro;
const state = game.getState();

// 当前阶段允许出牌时，使用状态中的卡牌实例 ID。
const result = await game.dispatch({
  type: 'play_hand',
  cardIds: [/* 选中的卡牌 ID */],
});
```

这里只定义游戏接口；策略函数的形参、返回格式以及注入方式不属于游戏 API。

## 操作必须覆盖完整流程

| 类别 | 操作 |
| --- | --- |
| 开局/重开 | `new_game`：指定 seed、牌组、难度开始一局 |
| 盲注 | 选择、跳过、规则允许时刷新 Boss |
| 手牌 | 出牌、弃牌、调整顺序 |
| Joker | 调整顺序、出售 |
| 消耗品 | 使用、指定目标、出售、规则允许的排序 |
| 商店 | 购买卡/优惠券/包、买入并使用、刷新、离开 |
| 开包 | 选择卡牌、指定目标、跳过剩余选项 |
| 结算 | 收款、继续、进入 Endless 等规则要求的确认 |

使用稳定的卡牌实例 ID、商品 ID 和包选项 ID，不依赖屏幕坐标。计分顺序以当前手牌和 Joker 的实际排列为准，需要改变顺序时调用排序操作。

`getState()` 至少包含 phase、revision、Ante/盲注、目标/累计分数、出牌/弃牌次数、资金、可见手牌、Joker 及成长值、消耗品、牌型等级、商店/开包选项、当前可执行操作及选牌约束、终局结果。操作约束可以表示选牌数量和强制牌，不需要枚举所有选牌组合。

默认观察状态应对应玩家可见信息；完整内部快照、未来牌序和随机状态若另行提供，应清楚区分。页面内的视图区分是数据使用约定，不应宣称能隔离已在同一页面执行的代码。

## 规则与画面

`dispatch` 完成一次规则操作并到达下一个允许决策的阶段后返回。动画根据内核生成的有序事件在游戏内部播放；计分与随机性不依赖动画帧数、播放速度或特效完成回调。

正常人工游玩按事件展示过程，快速调用可由表现层加速或跳过动画。画面落后于规则状态时，应避免人工根据旧画面继续操作。若确有原版允许且会影响规则的中间操作窗口，应在阶段模型中保留，不能直接合并掉；是否存在这样的窗口需实机核实。

同一实例内的操作按确定顺序提交。异步操作尚未完成时，明确拒绝冲突调用或按约定串行处理；接口文档必须说明行为。首版调用示例使用 `await`，不增加网络重试、HTTP 动作去重等协议层。

## 无界面使用与平台分工

SDK 模块可额外导出 `createGame(options)`，直接创建不带渲染器的游戏实例，并使用同一套 `GameAPI`。创建实例不能隐式访问 DOM；绑定 `window.balatro` 的工作放在网页入口。

这样平台可以导入内核/SDK 创建独立对局，或接入当前网页实例。并行数量、Worker/进程管理、策略执行与结果汇总属于平台。游戏项目不提供独立批量服务；后续是否支持特定 Node/Worker 环境，以实际构建验证为准。

完整快照导入导出可作为 SDK 扩展，支持平台复现；快照应保存规则版本、卡牌顺序、成长值、待决阶段和确定性随机状态。固定版本、seed 与同一操作序列应能复现结果。具体 RNG 与数值语义在内核方案定案后固定，不宣称已兼容原版 seed。

## 项目组织

实现阶段建议使用独立项目 `balatro-web`。首版按一个 Vite 项目组织即可：

```text
balatro-web/
  src/
    core/          # 独立规则、状态、内容定义、随机性
    sdk/           # GameAPI、createGame、状态与操作类型
    ui/            # React / PixiJS、页面入口、window.balatro 绑定
  docs/            # 操作接口与示例
```

这里只更新方案，不创建或发布新仓库。

## 现有项目的取舍

按当前需求，应优先考察可以直接在浏览器运行的 TypeScript/JavaScript 实现，并核实规则完整度和许可，再决定复用还是自研。Balatro.ts / Webatro 的现有网页结构更接近目标，但尚不能证明它们已经完整实现原版或提供了稳定的可注入接口。

Jackdaw 的独立内核、规则覆盖及计分事件值得参考，但其 Rust/Python 与 HTTP 接口不能直接替代浏览器 JS SDK。只有验证 Rust 核心能以 WASM 等方式在浏览器独立运行、状态与操作绑定合适后，才能把它作为本项目内核候选。现阶段不因其有 HTTP API 就优先采用，也不为接入它新增游戏服务端。详见 [10：开源复刻与模拟器对比](10-open-source-alternatives.md)。

## 验收重点

1. 静态网页能完成人工游玩的一局。
2. 页面 JavaScript 能通过公开接口读取状态并完成整局操作，无需模拟点击。
3. API 操作和画面推进的是同一个实例；人工与脚本使用相同规则。
4. 规则模块可脱离渲染器创建实例；非法操作不修改状态，固定 seed 的动作可复现。
5. 对外接口有类型、错误约定、完整操作说明和最小调用示例。
